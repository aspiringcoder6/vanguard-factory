# Agent Memory (Cognee) — hướng dẫn sử dụng

Agent Memory là **bộ nhớ tri thức dùng chung của dự án**. Người ta đưa tài liệu (yêu cầu, thiết kế,
quy trình) và mã nguồn vào một nơi; hệ thống đọc, nối các mối liên hệ giữa chúng và ghi nhớ. Từ đó,
mỗi khi agent nhận việc, nó **tra cứu bộ nhớ này thay vì phải đọc lại toàn bộ hồ sơ**.

Bộ nhớ gồm **ba kho, mỗi kho đảm nhiệm một việc**:

| Kho | Việc của kho | Ví dụ câu hỏi agent hỏi được |
|---|---|---|
| **Kho hồ sơ** (relational) | Lưu dữ liệu có cấu trúc: tài liệu, nguồn gốc | "Tài liệu này thuộc dự án nào, phiên bản nào?" |
| **Kho liên hệ** (graph) | Nối quan hệ giữa các thông tin | "Chức năng X dựa trên yêu cầu nào, sửa ảnh hưởng phần nào?" |
| **Kho tìm kiếm theo ý nghĩa** (vector) | Tìm theo nội dung, không cần đúng từ khóa | "Quy định về phân quyền ở tài liệu nào?" |

Agent làm việc với bộ nhớ qua **cổng giao tiếp MCP** — cùng một cách mà agent dùng để gọi công cụ,
nên không cần học cách kết nối mới. Cả ba kho và mô hình AI đều **thay đổi được qua cấu hình**
(SQLite ↔ PostgreSQL, Kuzu ↔ Neo4j, LanceDB ↔ pgvector; GLM ↔ OpenAI, Azure, Ollama) mà quy trình
nạp – tra cứu giữ nguyên: [kiến trúc chi tiết](/docs/architecture/tang-3-harness/cognee-agent-memory).

## Khi nào dùng Memory, khi nào không

| Dùng Memory | Không dùng Memory |
|---|---|
| Hỏi về tri thức dự án: yêu cầu, thiết kế, quy ước, kinh nghiệm các run trước | Đọc trạng thái runtime: job Workloop, session agent, tiến độ node |
| Tìm đoạn tài liệu gốc để dẫn chứng, trích quy định | Lấy artifact và bằng chứng kiểm thử — nằm ở backend Sandbox/TestForge |
| Tìm quan hệ: chức năng → yêu cầu → dữ liệu → mã nguồn | Lưu trữ file làm việc — dùng [VFS của Sandbox Kit](/docs/user-guides/sandbox-kit/gioi-thieu) |

## Kiểm tra nhanh bộ nhớ đang hoạt động

```bash
curl http://<memory-server>:8010/health
```

**Kết quả đúng phải thấy:** phản hồi có `status: ready` và `health: healthy`.
